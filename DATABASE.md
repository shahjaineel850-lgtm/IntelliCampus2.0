# IntelliCampus 2.0 Database Documentation

## Overview

IntelliCampus 2.0 uses **PostgreSQL 16** as the primary database for production deployment and **SQLite** as an optional local development database.

## Database Configuration

### Production (Docker)
```yaml
Host: db
Port: 5432
Database: auroraclassroom
User: aurora
Password: aurorasecret (change in production)
Connection URL: postgresql+asyncpg://aurora:aurorasecret@db:5432/auroraclassroom
```

### Development (Local)
- **Default**: SQLite (file-based): `./auroraclassroom.db`
- **Optional**: PostgreSQL on localhost:5432

### Environment Configuration
Configure in `.env` file:
```
DATABASE_URL="postgresql+asyncpg://aurora:aurorasecret@localhost:5432/auroraclassroom"
SYNC_DATABASE_URL="postgresql://aurora:aurorasecret@localhost:5432/auroraclassroom"
```

## Database Tables & Schema

### 1. **users** — User Accounts & Roles
```sql
CREATE TABLE users (
    id VARCHAR(36) PRIMARY KEY,
    name VARCHAR(120) NOT NULL,
    email VARCHAR(254) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    roles JSON DEFAULT '[]',
    status VARCHAR(20) DEFAULT 'ACTIVE',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

**Purpose**: Stores faculty and student user accounts
- `roles`: JSON array of user roles (e.g., `["FACULTY"]`, `["STUDENT"]`)
- `status`: Account status (ACTIVE, INACTIVE, SUSPENDED)
- Indexed on: `email`

---

### 2. **courses** — Course Management
```sql
CREATE TABLE courses (
    id VARCHAR(36) PRIMARY KEY,
    code VARCHAR(30) UNIQUE,
    title VARCHAR(180) NOT NULL,
    description TEXT,
    term VARCHAR(60) DEFAULT 'Fall 2026',
    faculty_ids JSON DEFAULT '[]',
    student_ids JSON DEFAULT '[]',
    status VARCHAR(20) DEFAULT 'ACTIVE'
);
```

**Purpose**: Stores course information
- `code`: Unique course code (e.g., "CS101")
- `faculty_ids`: JSON array of assigned faculty UUIDs
- `student_ids`: JSON array of enrolled student UUIDs
- Indexed on: `code`

---

### 3. **assignments** — Course Assignments
```sql
CREATE TABLE assignments (
    id VARCHAR(36) PRIMARY KEY,
    course_id VARCHAR(36) FOREIGN KEY NOT NULL,
    title VARCHAR(180) NOT NULL,
    instructions TEXT,
    due_at VARCHAR(40),
    max_score FLOAT DEFAULT 100,
    topic_tags JSON DEFAULT '[]',
    rubric JSON DEFAULT '[]',
    status VARCHAR(20) DEFAULT 'PUBLISHED'
);
```

**Purpose**: Stores assignment/activity details
- `topic_tags`: JSON array of learning topic tags
- `rubric`: JSON array of grading rubric criteria
- `status`: PUBLISHED, DRAFT, CLOSED
- Indexed on: `course_id`

---

### 4. **submissions** — Student Submissions
```sql
CREATE TABLE submissions (
    id VARCHAR(36) PRIMARY KEY,
    assignment_id VARCHAR(36) FOREIGN KEY NOT NULL,
    student_id VARCHAR(36) FOREIGN KEY NOT NULL,
    submitted_at VARCHAR(40),
    status VARCHAR(20) DEFAULT 'SUBMITTED',
    content TEXT,
    file_url VARCHAR(500),
    score FLOAT,
    feedback TEXT,
    graded_at VARCHAR(40),
    UNIQUE(assignment_id, student_id)
);
```

**Purpose**: Stores student submissions and grades
- `status`: SUBMITTED, GRADED, RESUBMITTED
- Indexed on: `assignment_id`, `student_id`

---

### 5. **recommendations** — Personalized Learning Recommendations
```sql
CREATE TABLE recommendations (
    id VARCHAR(36) PRIMARY KEY,
    student_id VARCHAR(36) FOREIGN KEY NOT NULL,
    course_id VARCHAR(36) FOREIGN KEY NOT NULL,
    title VARCHAR(180) NOT NULL,
    reason TEXT NOT NULL,
    topic VARCHAR(120),
    resource_ids JSON DEFAULT '[]',
    practice_items JSON DEFAULT '[]',
    status VARCHAR(20) DEFAULT 'NEW',
    created_at VARCHAR(40)
);
```

**Purpose**: AI-generated personalized recommendations for students
- `reason`: Explanation of why recommendation was generated
- `resource_ids`: JSON array of recommended resource IDs
- `practice_items`: JSON array of practice problems
- Indexed on: `student_id`, `course_id`

---

### 6. **alerts** — Academic Risk Alerts
```sql
CREATE TABLE alerts (
    id VARCHAR(36) PRIMARY KEY,
    course_id VARCHAR(36) FOREIGN KEY NOT NULL,
    student_id VARCHAR(36) FOREIGN KEY NOT NULL,
    type VARCHAR(60),
    severity VARCHAR(20),
    title VARCHAR(180) NOT NULL,
    description TEXT NOT NULL,
    evidence JSON DEFAULT '[]',
    created_at VARCHAR(40),
    acknowledged_at VARCHAR(40),
    acknowledged_by VARCHAR(36)
);
```

**Purpose**: Stores academic risk alerts generated by analytics
- `type`: Alert type (e.g., "LOW_ENGAGEMENT", "ASSIGNMENT_OVERDUE", "GRADE_DROP")
- `severity`: HIGH, MEDIUM, LOW
- `evidence`: JSON array with supporting data/metrics
- Indexed on: `course_id`, `student_id`

---

### 7. **interventions** — Intervention Tracking
```sql
CREATE TABLE interventions (
    id VARCHAR(36) PRIMARY KEY,
    student_id VARCHAR(36) FOREIGN KEY NOT NULL,
    course_id VARCHAR(36) FOREIGN KEY NOT NULL,
    type VARCHAR(60),
    owner_id VARCHAR(36) FOREIGN KEY NOT NULL,
    due_at VARCHAR(40),
    status VARCHAR(30) DEFAULT 'PLANNED',
    notes TEXT,
    outcome TEXT,
    created_at VARCHAR(40)
);
```

**Purpose**: Tracks faculty interventions for at-risk students
- `type`: Intervention type (e.g., "TUTORING", "MEETING", "RESOURCE_PROVIDED")
- `owner_id`: Faculty member managing the intervention
- `status`: PLANNED, IN_PROGRESS, COMPLETED
- Indexed on: `student_id`, `course_id`

---

### 8. **attendance** — Class Attendance Records
```sql
CREATE TABLE attendance (
    id VARCHAR(36) PRIMARY KEY,
    course_id VARCHAR(36) FOREIGN KEY NOT NULL,
    student_id VARCHAR(36) FOREIGN KEY NOT NULL,
    date VARCHAR(20),
    status VARCHAR(20) DEFAULT 'PRESENT',
    remarks TEXT,
    recorded_by VARCHAR(36) FOREIGN KEY,
    created_at VARCHAR(40),
    UNIQUE(course_id, student_id, date)
);
```

**Purpose**: Tracks class attendance
- `status`: PRESENT, ABSENT, LATE, EXCUSED
- `recorded_by`: Faculty member who recorded attendance
- Indexed on: `course_id`, `student_id`, `date`

## Database Migrations

The project uses **Alembic** for database schema versioning and migrations.

### Running Migrations
```bash
# Inside backend container or local environment
cd backend
alembic upgrade head
```

### Creating New Migrations
```bash
alembic revision --autogenerate -m "Description of changes"
alembic upgrade head
```

### Migration Files Location
```
backend/migrations/versions/
```

## Database Backup & Restore

### Backup PostgreSQL Database
```bash
# From container
docker exec aurora_postgres pg_dump -U aurora -d auroraclassroom > backup.sql

# Or locally
pg_dump -U aurora -h localhost -d auroraclassroom > backup.sql
```

### Restore from Backup
```bash
# From container
docker exec -i aurora_postgres psql -U aurora -d auroraclassroom < backup.sql

# Or locally
psql -U aurora -h localhost -d auroraclassroom < backup.sql
```

## Database Relationships

```
users
  ├─ courses (faculty_ids, student_ids)
  ├─ submissions (student_id)
  ├─ recommendations (student_id)
  ├─ alerts (student_id, acknowledged_by)
  ├─ interventions (student_id, owner_id)
  └─ attendance (student_id, recorded_by)

courses
  ├─ assignments (course_id)
  ├─ recommendations (course_id)
  ├─ alerts (course_id)
  ├─ interventions (course_id)
  └─ attendance (course_id)

assignments
  └─ submissions (assignment_id)
```

## Performance Optimization

### Indexes
The following columns are automatically indexed for fast queries:
- `users.email`
- `courses.code`
- `assignments.course_id`
- `submissions.assignment_id`
- `submissions.student_id`
- `recommendations.student_id`
- `recommendations.course_id`
- `alerts.course_id`
- `alerts.student_id`
- `interventions.student_id`
- `interventions.course_id`
- `attendance.course_id`
- `attendance.student_id`
- `attendance.date`

### Query Optimization Tips
- Always filter by `course_id` or `student_id` when possible
- Use `attendance.date` index for date range queries
- Consider pagination for large result sets (assignments, submissions)
